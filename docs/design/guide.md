# Руководство

## 1. Как устроены токены

Два слоя:

- **Примитивы** (`primitive.color.neutral.1…12`, `primitive.color.accent.1…10`, `green/amber/coral.500`) — сырая палитра. **В компонентах не используются.**
- **Семантические токены** (`color.*`, `font.*`, `space.*`, `radius.*`, `shadow.*`, `size.*`, `motion.*`, `z.*`, `layout.*`) — ссылаются на примитивы. Компоненты используют только их.

Так светлую тему можно будет добавить позже: переопределить семантические токены на `[data-theme="light"]`, не трогая компоненты.

Отдельная группа **`game.*`** — цвета из игры. Не смешивается с UI-цветами (раздел 3).

Имена совпадают в обоих форматах: путь `color.text.secondary` в JSON = переменная `--color-text-secondary` в CSS.

## 2. Какой цвет брать

### Фоны (снизу вверх)

| Токен | Где |
|---|---|
| `color.bg.app` | Фон окна, фон центральной области модуля |
| `color.bg.surface` | Карточки, сайдбар, шапка окна, строка статусов, панель «Текущий предмет» |
| `color.bg.raised` | То, что лежит поверх surface: шапки таблиц, меню, поповеры, Ctrl+K |
| `color.bg.hover` | Hover строк и вторичных кнопок |
| `color.bg.active` | Нажатое состояние, подсвеченный пункт меню |
| `color.bg.selected` | Выбранный пункт навигации, активный фильтр |
| `color.bg.overlay` + `blur.overlay` | Только виджет оверлея поверх игры |
| `color.bg.scrim` | Затемнение под модальным окном |

### Текст

| Токен | Где | Нельзя |
|---|---|---|
| `color.text.primary` | Основной текст, значения модов, цены, имена | — |
| `color.text.secondary` | Подписи, диапазоны `(100–109)`, класс предмета, вторичные данные | — |
| `color.text.muted` | Подписи групп навигации, хинты в основном окне | **В оверлее** (контраст падает до 4.2) |
| `color.text.disabled` | Неактивные элементы | Для информации, которую нужно прочитать |
| `color.text.accent` | Ссылки, призрачные кнопки, T1, активные иконки | Для длинного текста |
| `color.text.on-accent` | Текст на `color.accent.solid` | Белый текст на акценте (3.5:1) |

### Рамки

`color.border.subtle` — разделители внутри карточки; `color.border.default` — рамки карточек и полей; `color.border.strong` — вторичные кнопки, поле в hover; `color.border.focus` — кольцо фокуса.

### Акцент

Малиново-розовый — **только для интерактива и выделения**: основная кнопка, фокус, выбранный пункт, активная вкладка, включённый переключатель, лучший тир (T1). Не для заголовков, не для декора, не для статусов.

### Статусы

`color.status.{success|warning|danger|info}.{fg|bg|border}`. Плашка = `bg` + `border` + иконка + текст цвета `fg`.

- Статус **всегда с иконкой**: ✓ success, ▲ warning, ⬣ danger, ⓘ info.
- `danger` — коралловый, а не красный: красный занят `game.state.corrupted`.
- `info` — нейтральный: синие оттенки заняты игрой (Magic, Crafted, Divination).

## 3. Игровые цвета (`game.*`)

1. Используются **только для того, что они значат в игре**: редкость предмета, тип мода, состояние предмета, цвет сокета. Никогда — для кнопок, статусов, графиков, декора.
2. **Смысл никогда не передаётся только цветом.** Всегда пара «цвет + текст или форма»:
   - редкость — бейдж с текстом `RARE` / `UNIQUE` / `MAGIC`… в рамке цвета редкости, имя предмета тем же цветом;
   - тип мода — тег с текстом `crafted` / `fractured` / `implicit` / `enchant` (у crafted рамка пунктиром);
   - состояние — бейдж `◆ CORRUPTED` (ромб + текст), `MIRRORED` и т. п.;
   - сокет — кружок с буквой `R` / `G` / `B` / `W`.
3. `game.rarity.unique` и `game.state.corrupted` **осветлены** относительно игры ради контраста. Исходники лежат в `game.raw.*` — только для справки, в UI не использовать.
4. Текст явных модов — `color.text.primary`, **а не синий, как в игре**: синий в нашем UI означает Magic. Цвет получают только crafted и fractured моды.
5. Акцент интерфейса никогда не подменяет игровой цвет и наоборот.

## 4. Правила оверлея

Оверлей — отдельное прозрачное окно поверх игры, которое появляется у курсора по горячей клавише. На него смотрят 1–3 секунды.

- Фон: `color.bg.overlay` (94%) + `backdrop-filter: blur(var(--blur-overlay))`, тень `shadow.overlay`, радиус `radius.xl`. Не делать фон прозрачнее — над светлыми локациями текст перестанет проходить AA.
- Ширина `layout.overlay.width` (440), допустимо 360–480. Плотность — `data-density="compact"`.
- Минимальный размер текста **13 px** (`font.size.label`). `font.size.caption` (12 px) в оверлее запрещён.
- Минимальный цвет текста — `color.text.secondary`. `muted` не использовать.
- Появление — мгновенно (`motion.duration.instant`), скрытие — `motion.duration.fast`. Никаких выездов и пружин.
- Порядок сверху вниз: редкость и имя → базовые свойства → моды (P/S, значение, диапазон, тир) → состояние → цена → действия.
- Панель не должна выходить за край экрана: ставить слева или справа от курсора, где есть место.

## 5. Числа

- Весь UI с `font-feature-settings: "tnum" 1` (уже в `tokens.css` на `html`).
- Значения модов, диапазоны, тиры, цены, количества, клавиши — шрифт `font.family.mono`.
- Значение мода — `semibold` + `text.primary`; диапазон — `regular` + `text.secondary`: `+105 (100–109)`.
- Приблизительная цена — со знаком `~`: `~120 chaos`. Пересчёт — с `≈`: `≈ 0.6 divine`.

## 6. Чего делать нельзя

- Хардкодить цвета, размеры, тени, радиусы в компонентах — только токены.
- Использовать примитивы напрямую в компонентах.
- Красить UI в игровые цвета или передавать смысл только цветом.
- Использовать белый текст на акценте.
- Делать прокрутку внутри окна приложения на 1440×900 (см. `app-shell.md`). Если данных больше, чем места, — постраничный вывод, а не скролл.
- Обрезать подписи навигации многоточием: подписи пишутся так, чтобы помещались (≈ 22 символа при ширине сайдбара 256).
- Рисовать любые элементы автоматизации действий в игре: «Авто», «Старт/стоп», «Запустить крафт» и т. п. Правило игры: одна клавиша — одно действие игрока. Приложение только считает и подсказывает.
- Использовать шрифты, логотипы и арт Grinding Gear Games так, чтобы продукт выглядел официальным.
- Добавлять градиенты, свечения и цветные полосы слева у карточек ради украшения.
